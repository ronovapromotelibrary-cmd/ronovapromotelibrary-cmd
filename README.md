## Development Workflow

My preferred development workflow emphasizes clear requirements, practical implementation, and verification.

1. Understand the requirements and intended users.
2. Define project scope, constraints, and acceptance criteria.
3. Plan the architecture and data flow.
4. Design the user experience and interface.
5. Implement the required functionality.
6. Integrate APIs and databases where appropriate.
7. Test core user journeys and failure cases.
8. Review security, privacy, and error handling.
9. Document setup steps, configuration, and known limitations.
10. Verify functionality before publishing.
11. Maintain the project and improve it based on evidence.

## Development Principles

- **Real functionality:** Prefer working features over fake demonstrations.
- **Honest status:** Distinguish planned, in-development, testing, released, maintained, and archived projects.
- **Clear requirements:** Define expected behavior before implementation.
- **Maintainability:** Prefer understandable, organized code.
- **Responsive design:** Support different screen sizes.
- **Accessibility:** Keep content and controls understandable and usable.
- **Security:** Never expose secrets or credentials.
- **Error handling:** Explain failures clearly and provide safe recovery paths where possible.
- **Testing:** Verify important workflows before release.
- **Documentation:** Explain setup, configuration, and limitations.
- **Continuous improvement:** Refine implementations as requirements evolve.
